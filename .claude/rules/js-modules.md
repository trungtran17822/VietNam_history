# Frontend modules (Vite + React + TypeScript)

- ES modules under `frontend/src/`, TypeScript strict. No `window` globals.
- Domain logic stays UI-free in `src/lib/` (engine, storage, lesson schema, class-session client, auth, audio, text) and gets a Vitest test in `src/lib/*.test.ts`. Components never touch `localStorage` keys directly; go through `lib/storage.ts`, `lib/prefs.ts` or `lib/class-session.ts`.
- Routes are files in `src/routes/` (TanStack Router, hash history); `src/routeTree.gen.ts` is generated by the Vite plugin, never edit it. Keep route files thin; screens live in `src/components/`.
- Lessons are data: one JSON per lesson in `src/content/lessons/<id>.json`, validated by `src/lib/lesson-schema.ts` (zod). Simulation behaviour belongs in lesson coefficients, not in `engine.ts`.
- three.js is only imported by `src/scene/silk-map.ts`, which is loaded lazily. Do not import it (or `silk-map.ts` values) from anything in the initial bundle; `import type` is fine.
- Mark deliberate simplifications with a `// ponytail:` comment.
- After editing, run `npm run check` (tsc, lesson schema, labels, NFC, backend syntax), then `npm run test:unit`, and `npm run test:e2e` for UI changes.
